# Reference Use Policy

## Why reference documents exist

External or prior-game references in this repository exist to communicate product qualities, failure modes, genre expectations and designer vocabulary to Codex.

They are **not implementation specifications** unless a Project Saturday product spec explicitly adopts a design decision.

## Priority

When documents disagree, use this order:

1. current Project Saturday product specs;
2. current approved product-review/correction documents;
3. architecture/ADR decisions;
4. execution plans;
5. reference documents such as `THE_ROOKIE_BEHAVIORAL_REFERENCE.md`.

Reference documents explain *why*. Project Saturday specs decide *what to build*.

## Originality rule

References may inspire:

- clarity;
- pacing;
- information architecture principles;
- categories of strategic tension;
- feedback quality;
- genre conventions.

They must not be used to copy protected or proprietary expression, content, assets, data, code or distinctive presentation.

If Codex believes a Project Saturday implementation is becoming a renamed or reskinned reproduction of a reference product, stop that line of implementation, document the concern, and choose a more football-specific original solution.
